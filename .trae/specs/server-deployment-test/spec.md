# 服务器部署测试规范

## 为什么
需要验证农产品二维码追溯系统的现有内容是否能在服务器上正常运行，包括前端、后端和数据库的集成部署。

## 什么变更
- 测试Django后端服务能否正常启动
- 测试React前端能否正常构建和运行
- 测试Docker容器化部署是否成功
- 测试Nginx反向代理配置是否正确
- 测试数据库连接和迁移是否成功

## 影响
- 受影响的规格：整个系统的部署和运行
- 受影响的代码：所有服务器相关配置文件

## 新增需求
### 需求：服务器部署测试
系统应该能够在服务器环境中成功部署和运行。

#### 场景：服务器环境准备测试
- **给定**：服务器环境（Ubuntu 24.04）
- **当**：执行部署脚本或手动部署命令
- **那么**：所有服务应该成功启动且可访问

#### 场景：Docker容器部署测试
- **给定**：Docker和Docker Compose已安装
- **当**：执行`docker-compose up -d`
- **那么**：所有容器应该成功启动且运行正常

#### 场景：前端页面访问测试
- **给定**：前端服务已启动
- **当**：访问前端页面
- **那么**：页面应该正常加载且无错误

#### 场景：后端API访问测试
- **给定**：后端服务已启动
- **当**：访问API端点
- **那么**：API应该返回正确的响应

## 测试检查点
1. 后端依赖安装成功（Django、DRF等）
2. 数据库迁移成功
3. 后端服务启动成功（端口8000）
4. 前端依赖安装成功
5. 前端构建成功
6. Nginx配置正确
7. Docker容器运行正常
8. 前后端集成正常
